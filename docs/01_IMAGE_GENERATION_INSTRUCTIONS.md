# 《AI는 거짓말을 하지 않는다》 이미지 생성 지시문
## 별도 이미지 세션용 · Episode 01 전체 아트 선행 제작

문서 ID: `ANL-ART`; 버전: `1.0.0`; 계약: `art.v1`; 작성 기준일: `2026-09-14`.
반드시 같은 폴더의 `00_MASTER_PLAN.md`를 먼저 읽는다. 이 세션은 **이미지만 완성하고 코드 개발 세션으로 인계하는 세션**이다. 게임 프로젝트는 아직 없다. 코드 세션과 대화 기억을 공유한다고 가정하지 않는다.

> 최종 목표: 아래 54개 런타임 PNG를 지정한 파일명·크기로 완성하고, 실제 파일을 검수해 `manifest.lock.json`과 `ASSET_READY.json`으로 인계한다. 파일명 목록이나 이미지 프롬프트만 작성한 상태는 이미지 완료가 아니다. 이 문서 자체를 전달받은 지금 이미지가 이미 만들어져 있다고 오해하지 말 것.

## 3. 아트 디렉션

### 3.1 공통 스타일
성인 대상의 현대적 한국어 추리 비주얼노벨. 절제된 애니메이션 일러스트와 편집 일러스트의 중간 정도. 현실적인 성인 비율, 명확한 윤곽, 부드러운 셀 음영, 자극적이지 않은 차가운 야간 톤. 고채도 사이버펑크 네온, 판타지 갑옷, 미성년처럼 보이는 인물, 미소녀 수집게임식 성적 강조를 쓰지 않는다. 주요 인물의 나이가 외형에서 느껴져야 한다. 모든 인물을 같은 젊은 얼굴로 그리지 않는다.

배경은 푸른 회색·차콜 중심이지만 검게 뭉개지지 않아야 한다. UI를 올릴 면은 차분하고, 단서 대상과 얼굴은 충분한 명도 대비를 갖는다. 빛은 좌측 전면의 부드러운 중성 키라이트를 공통으로 사용하고 외곽에 아주 약한 청색 환경광만 허용한다. 실제 회사 로고, 차량 브랜드, 신문사 로고, 워터마크는 사용하지 않는다. 회사명 NEOVIA도 **글자가 필요한 곳은 코드로 표시**한다.

카메라는 일반 배경은 눈높이의 35~50mm 상당 느낌, 인물은 흉부~허벅지 중간이 들어오는 정면 또는 3/4 반신이다. 극단적인 광각·어안·위아래 원근은 금지한다. 법정이 아니라 기술 사고조사위원회이므로 법봉·판사 가발·법복을 넣지 않는다.

### 3.2 인물 표정 차분의 고정점
모든 인물 PNG는 1024×1536 RGBA. 발은 필요 없으며 머리 꼭대기와 손은 잘리지 않게 한다. 공통 anchor는 이미지 하단 중심 `(0.5, 1.0)`; 눈높이 목표는 이미지 위에서 0.20~0.25. 인물의 몸통 너비와 눈높이는 같은 인물 표정 간 ±2% 범위의 정합을 목표로 한다. 기준 표정에서 승인한 머리·의상·액세서리·포즈·빛·크롭을 고정하고 얼굴 표정만 바꾼다. 표정마다 전혀 다른 제스처나 카메라를 쓰지 않는다.

투명 격자무늬를 그린 가짜 투명 배경은 불합격. 알파 채널은 실제 0 값의 여백을 포함해야 하고 얼굴·옷 안쪽이 반투명해지면 안 된다. 머리카락 가장자리의 부드러운 알파는 허용하되 흰 테두리·검은 번짐·배경 잔여가 없어야 한다. 어두운 배경과 밝은 배경 양쪽에 합성해 검사한다.

### 3.3 이미지로 생성하지 않는 것
증거 문서의 글자, Git diff의 코드, 로그, 41%·94.7%·91.2·71·-8.1·-2.0·-6.2 등의 수치, 타임스탬프, 이메일·회의록, 책임표, 신호 색의 판정 표시, 인식 bounding box, 센서 포인트클라우드, 재구성 연결선, 버튼·탭·툴팁·선택 테두리, 회사 로고 텍스트, 제목 로고 텍스트는 **코드/UI 데이터 담당**이다. 이런 항목 때문에 추가 이미지 생성 목록을 늘리지 않는다.

종이 문서 질감을 증거마다 새로 생성할 필요도 없다. 코드는 단색 패널·선·텍스트로 읽을 수 있는 문서를 만든다. 증거 이미지가 없다는 이유로 파일을 만들라는 요청을 하지 않는다. 마스터의 “별도 생성 이미지 없음”이 정상적인 설계다.

### 3.4 생성 문장 공통 금지 조건
```text
이미지 안에 글자, 숫자, 한글, 영문, UI 버튼, 타이틀, 자막, 워터마크,
게임 화면 프레임, 대화창, 타임스탬프, 인식 박스, 정답선, 콜라주,
여러 표정 시트, 여러 장면 시트, 실제 브랜드를 넣지 않는다.
과도한 네온, 과장된 신체 비율, 성적 강조, 미성년 외형, 고어,
시신, 혈흔, 신체 훼손, 범인임을 암시하는 악마 눈이나 악역 조명을 쓰지 않는다.
```

## 4. 해상도·후처리·파일 규칙

모든 최종 산출물은 PNG, sRGB 해석을 전제로 한 RGB 또는 RGBA 8bit다. TIFF·JPEG·WebP를 `.png`로 확장자만 바꾸면 안 된다. 생성 원본은 다른 규격이어도 `art_source/originals`에 보존하고 최종 파일을 정확한 크기로 만든다. 늘여서 비율을 찌그러뜨리지 않는다.

| 종류 | 최종 크기 | 후처리 원칙 |
| --- | --- | --- |
| 배경·CG | 1920×1080 | 원비율 유지 후 주변부 안전 크롭, 주요 대상 잘림 금지 |
| 인물 | 1024×1536 RGBA | 투명 캔버스로 맞추고 동일 anchor·눈높이 유지 |
| 영상형 사건 이미지 | 목록 지정 1920×1080 또는 1600×900 | 단서 영역 보존, 코너 타임코드는 코드 |
| 물건·사진 | 1024×1024 또는 1600×900 | 물체 전체와 오버레이 가능 면 보존 |

해상도 수치가 지원되지 않는 도구에 존재하지 않는 인자를 전달하지 않는다. 가능한 큰 규격·가까운 비율로 생성한 뒤 원본과 최종 규격을 manifest에 모두 기록한다. 확대가 필요하면 확대 사실을 남기고 디테일 손실을 점검한다. 업스케일이 실제 원본 디테일을 복구했다고 주장하지 않는다. 주요 단서 영역을 손상시키는 크롭보다 재생성 또는 여백 확장을 선택한다.

파일명은 아래 명세와 **대소문자까지 동일**해야 한다. `final2`, `new`, `(1)` 같은 접미사는 후보 폴더에만 허용한다. 런타임 폴더에서는 계약상 이름 1개만 남긴다. 최종 해시를 쓴 뒤 파일을 다시 저장하면 반드시 manifest와 READY 해시를 갱신한다.

## 6. 생성 순서와 레퍼런스 잠금

**A. 기준 이미지:** `ev_vehicle_side`, `chr_nari_neutral`, `chr_han_composed`, `bg_hearing_room`을 먼저 만든다. 차량의 차체·식별선, 인물의 성인 비율·선화, 회의장의 조명 수준을 맞춘다. 네 파일은 최종 산출물 개수에 이미 포함돼 있으며 별도의 콘셉트 자산으로 중복 계산하지 않는다.

**B. 나머지 인물 기준 표정:** 아래 각 인물의 첫 표정을 만든다. 한 인물씩 기본 표정을 승인한 뒤 파생 표정으로 넘어간다. 승인된 기본 이미지를 실제 파일로 제공해 편집·참조한다. 같은 이름을 프롬프트에 적는 것만으로 얼굴이 고정된다고 가정하지 않는다.

**C. 배경·사건 시점:** 도로 기준 `bg_crosswalk_rain`→동일 구도 `bg_crosswalk_dawn`, 차량 외형→후방 범퍼·전방·후방·교차로 영상을 만든다. 후방 빈 차로와 외부 CCTV는 같은 도로 배치를 공유하지만 카메라 시점은 독립적이다. 정확한 차량 위치·시간·센서 데이터는 코드가 표시하므로 이미지의 우연한 작은 차이를 추리 근거로 사용하지 않는다.

**D. 표정 차분·CG:** 승인된 원본을 편집하여 표정만 바꾼다. CG의 인물 복장·차량은 승인본을 참조한다. 하나의 CG에 여러 인물이 나오는 경우 해당 실제 참조 파일들을 함께 제공한다. 얼굴이 작아서 정밀 일치 검사가 어려우면 자세·의상·헤어 실루엣은 반드시 맞춘다.

**E. 검수·잠금:** 전 파일 수·이름·크기·알파 검사, 인물 차분 나란히 보기, 밝고 어두운 배경 합성, 단서 영역 체크, 해시 기록, 최종 인계 순서다. 필요한 재생성은 이 단계에서 끝낸다. 사용자가 중간 승인 절차를 따로 요구하지 않았다면 매 이미지마다 질문하며 작업을 멈추지 말고 문서 기준으로 제작 담당자가 검수한다.

## 8. 단서 영역과 코드 연결

### 8.1 좌표 계약
단서 영역은 `x,y,width,height`를 0~1 정규화 값으로 기록한다. 원점은 **이미지 좌상단**, x는 오른쪽, y는 아래쪽이다. UI 스크린 좌표나 Unity pivot 좌표가 아니다. 좌표는 최종 PNG 규격 기준이다. 이미지가 contain 모드로 축소되면 코드가 표시된 실제 이미지 사각형에 맞춰 변환한다. 여백을 포함한 전체 패널 크기로 곱하면 안 된다.

계획값은 생성 모델이 정확히 맞출 수 있다고 보장하지 않는다. 실제 그림에서 영역을 측정해 `regions`에 기록하는 것이 우선이다. regionId는 바꾸지 않는다. 단서가 표시 가능한 중앙 영역에 오도록 그리는 것이 불가능하면 명시적으로 재생성한다. 전체 장면을 임의로 잘라 이미지만 맞추고 코드 측정값을 방치하지 않는다.

`bg_crosswalk_dawn`에는 p01을 위한 세 영역 `crosswalk`, `signal`, `vehicle`를 실제 구도에 맞춰 반드시 등록한다. 최초 계획값은 각각 `[0.15,0.67,0.64,0.20]`, `[0.78,0.18,0.10,0.33]`, `[0.40,0.49,0.26,0.22]`다. 이 배경에는 정차한 은회색 사건 차량이 보이거나, 현장 차량 위치 표지를 클릭할 수 있어야 한다. 사건 정보는 코드 패널로 열리므로 번호판·피해자 모습은 필요 없다.

`ev_cabin_base.warning_display`에는 EMERGENCY MANEUVER 경고를 코드로 표시한다. `ev_front_base.pedestrian`에는 인식 박스를 코드로 표시하되 상자가 보행자와 떨어지지 않아야 한다. `ev_phone_base.screen`에는 동의한 경우만 개인 문장을 표시한다. 다만 피해자 자료의 증거 썸네일은 `ev_victim_photo`가 대표다.

### 8.2 사고 영상의 정직한 표현
이번 범위는 실제 동영상 생성이 아니라 **자료 프레임+코드 오버레이+타임라인**이다. 재생 아이콘이 있어도 서로 다른 시각을 독립적으로 검증한 것처럼 임의 프레임을 만들어내지 않는다. 게임 내 표기는 “기록 프레임 보기” 또는 “재구성 재생”으로 구분한다. 코드로 크롭·팬·약한 비 연출을 줄 수 있지만 그런 효과 자체를 수사 증거로 취급하지 않는다.

## 9. manifest와 잠금 계약

### 9.1 계획 manifest
`manifest.plan.json`은 마스터의 목록을 빠짐없이 옮긴다. root는 객체이고 assets는 배열이다. 아래는 **스키마 설명용 예시 하나**이며 전체 인계본을 이 한 행으로 대체하지 않는다. 예시 상태는 완료를 뜻하지 않는다.

```json
{
  "schemaVersion": 1,
  "contractVersion": "art.v1",
  "documentVersion": "1.0.0",
  "episodeId": "ep01",
  "requiredAssetCount": 54,
  "assets": [
    {
      "id": "chr_nari_neutral",
      "path": "ep01/portraits/chr_nari_neutral.png",
      "kind": "portrait",
      "required": true,
      "width": 1024,
      "height": 1536,
      "alphaRequired": true,
      "status": "planned",
      "revision": 1,
      "sourceReferenceIds": [],
      "anchor": {
        "x": 0.5,
        "y": 1.0
      },
      "regions": [],
      "fitMode": "contain",
      "notes": "실제 파일 생성·검수 전"
    }
  ]
}
```
### 9.2 잠금 manifest
plan의 전체 목록을 복사하고 실측 필드를 채운다. `status=approved`는 해당 파일에 대한 기술 검사와 육안 검수가 모두 끝났을 때만 가능하다. `visualReviewBy`는 실제 검수자/에이전트 식별자를 기록하고 사람 이름을 만들어 쓰지 않는다. 제작 도구 정보는 아는 것만 기록한다. 이미지 생성 도구가 seed를 제공하지 않았으면 null이며 임의 수치를 쓰지 않는다.

필수 추가 필드:
```text
sha256             최종 PNG 실제 바이트의 SHA-256, 64자리 소문자 hex
fileBytes          실제 파일 바이트 수
actualWidth/Height 실제 디코드 크기, 계획 크기와 같아야 함
mode               RGB 또는 RGBA
alphaVerified      실제 알파 검사 결과
visualApproved     실제 그림 검수 결과
visualReviewBy     검수 주체
visualReviewNotes  얼굴·의상·한글 없음·단서 영역·투명 배경 확인 메모
generatedAtUtc     실제 생성 또는 파일 수신 시각; 모르면 null
sourceTool         사용한 실제 도구/모델 정보; 미노출이면 tool-reported-unknown
sourceNativeSize   후처리 전 실측 크기
processing         crop / resize / alpha-cleanup 등의 실제 후처리 이력
regions            최종 이미지에서 재측정된 정규화 좌표
```

성공적인 승인본에는 `reviewChecks`를 추가한다: `noBakedText`, `identityConsistent`, `compositionSafe`, `clueContentCorrect`, `alphaEdgesClean`. 인물이 아닌 파일의 identityConsistent, 불투명 파일의 alphaEdgesClean은 `not_applicable`로 표시할 수 있다. 판정 근거 없는 자동 true 채우기를 하지 않는다.

### 9.3 READY 파일
잠금 manifest 최종 저장 후 해당 파일의 바이트 해시를 계산한다. 모든 검사가 끝났을 때만 아래 ready를 true로 전환한다. 아래 예시는 의도적으로 미완료 상태다.

```json
{
  "schemaVersion": 1,
  "episodeId": "ep01",
  "contractVersion": "art.v1",
  "documentVersion": "1.0.0",
  "ready": false,
  "requiredAssetCount": 54,
  "approvedAssetCount": 0,
  "manifestPath": "handoff/art/manifest.lock.json",
  "manifestSha256": null,
  "masterDocumentSha256": null,
  "artInstructionSha256": null,
  "codeInstructionSha256": null,
  "verifiedAtUtc": null,
  "verificationReport": "handoff/art/ART_REVIEW.md",
  "blockers": [
    "이미지 생성과 실제 검수 전"
  ]
}
```

문서 해시는 세 MD의 실제 바이트로 계산한다. 문서를 한 줄 고치면 READY의 문서 해시를 갱신하고 변경 영향도 검토한다. 해시 일치는 인계 파일의 동일성을 확인하는 장치이며 아트 품질을 대신 증명하지 않는다.

## 10. 기계 검사와 시각 검수

### 10.1 기계 검사
파일 수가 맞아도 같은 그림을 이름만 바꿔 채웠는지 확인해야 한다. 전체 중복 해시는 원칙적으로 차단하고 예외는 명시적으로 허용한 파일만 인정한다. 이번 목록에는 의도적인 완전 중복 파일이 없다. 표정만 달라야 하는 파일이 동일 해시면 누락으로 본다.

다음 검사 도구는 이미지 생성 세션에서 `tools/validate_art.py`로 구현한다. 표준 라이브러리와 Pillow를 사용하며 이미지 생성·게임 코드 기능은 포함하지 않는다. 의존 설치는 격리된 Python 가상환경을 사용한다. 실행 예:
```bash
python3 -m venv .venv-art
. .venv-art/bin/activate
python -m pip install Pillow
python tools/validate_art.py   --plan handoff/art/manifest.plan.json   --manifest handoff/art/manifest.lock.json   --root art_delivery/runtime
```

검사 의사코드는 다음 계약을 빠짐없이 구현한다. 검사 스크립트를 만들었다는 사실과 실제로 실행했다는 사실을 구분해 보고한다.
```python
# 입력값을 먼저 검증한다. root/manifest의 절대 경로를 고정한다.
# 1) plan과 lock의 assetId 집합이 동일하고 required 개수가 54인지 확인한다.
# 2) id/path 대소문자 충돌, 중복 ID, 중복 경로, '..', 절대 경로를 거부한다.
# 3) root/path를 resolve한 결과가 root 안인지 확인한다. 외부 symlink는 거부한다.
# 4) 실제 PNG 시그니처와 디코딩 성공 여부를 확인한다. 확장자만 믿지 않는다.
# 5) Pillow Image.verify 후 다시 열어 크기·RGB/RGBA·알파를 검사한다.
# 6) 실제 크기가 plan의 width/height와 동일해야 한다.
# 7) alphaRequired이면 RGBA이고 완전 투명 여백과 불투명 인물 영역이 있어야 한다.
# 8) 불투명 파일은 알파가 있다면 전부 255인지 확인한다.
# 9) SHA-256과 fileBytes를 실제 파일에서 계산해 lock과 비교한다.
# 10) region 좌표가 0~1이고 영역 크기가 양수이며 바깥으로 넘치지 않는지 확인한다.
# 11) status=approved, visualApproved=true, 검수 주체·메모가 실제로 채워졌는지 확인한다.
# 12) 동일 SHA 파일, 계획 외 런타임 PNG, 빠진 필수 regionId를 보고한다.
# 실패는 non-zero exit code; JSON/MD 리포트에 id·path·원인·실측값을 기록한다.
```

`plan` 자체도 마스터 목록과 대조해야 한다. 생성 담당자가 plan에서 실패 자산을 삭제해 파일 수를 맞추는 것은 금지다. 대용량/비정상 이미지로 검사기가 멈추지 않게 최대 픽셀 수·파일 크기 제한을 둔다. 이 목록의 정상 해상도를 충분히 수용하는 상한을 사용한다.

### 10.2 시각 검수 체크리스트
| 분류 | 통과 기준 | 실패 예 |
| --- | --- | --- |
| 인물 동일성 | 같은 얼굴 골격·헤어·의상·액세서리 | 표정마다 다른 사람, 안경·나이 변화 |
| 포즈 정합 | 눈높이·몸통·손 위치가 크게 변하지 않음 | 표정 변경마다 캐릭터 점프 |
| 알파 | 밝고 어두운 합성에서 깨끗한 가장자리 | 격자무늬 배경, 흰 테두리, 옷 내부 구멍 |
| 성인 표현 | 직업·연령에 맞는 외형 | 임원과 엔지니어가 모두 학생처럼 보임 |
| 배경 연속성 | 도로·건물·차량 디자인 일치 | 새벽 배경이 다른 교차로로 변함 |
| 핵심 단서 | rear_empty·junction에서 가까운 뒤차 없음 | 장식으로 뒤차를 그려 사건 논리 훼손 |
| 텍스트 분리 | 모든 표시창·서류 라벨 무문자 | 틀린 시간·숫자·회사명 생성 |
| 비폭력 표현 | 사고의 긴장감만, 직접 훼손 없음 | 시신·피·충돌 신체 묘사 |
| UI 배치 | 대화창·패널이 핵심 대상 가리지 않음 | 인물 눈·경고창을 하단 대화창이 가림 |

각 파일을 실제 크기 100%와 예상 게임 표시 크기 두 가지로 확인한다. 인물별 접촉시트는 검수용으로만 생성 가능하다. 접촉시트를 런타임 파일 대신 납품하지 않는다. 전체 검수 내용은 `ART_REVIEW.md`의 파일별 행에 남긴다.

## 11. 완료 리포트와 인계

`ART_HANDOFF.md`에는 버전·총개수·완료개수, 실제 폴더 트리, 미해결 항목, 기준 이미지와 차분의 연결, 알파 후처리 유무, 좌표 수정 목록, 사용 도구/라이선스 정보 중 확인된 범위, lock 해시, 검사 명령과 실제 종료 코드를 포함한다. “전부 완료” 한 문장으로 끝내지 않는다.

코드 세션에 전달할 것은 **세 MD + art_delivery/runtime 전체 + handoff/art 전체**다. 대화창에 보여준 이미지 카드만으로 파일이 전달됐다고 가정하지 않는다. 원본 생성 파일과 후보는 보관하되 Unity에 임포트하지 않는다. 폰트 파일을 이 문서 패키지에 끼워 넣지 않는다. 코드 세션은 권한이 있는 폰트를 별도로 준비하고 출처를 기록한다.

### 11.1 작업 중단·재개
생성이 일부만 가능하면 완료된 파일을 보존하고 `ready=false`로 남긴다. 남은 ID와 현재 후보·실패 원인을 적어 다른 이미지 세션이 이어받을 수 있게 한다. 중단한 세션의 기억을 요구하지 않는다. 도구 이용 제한 때문에 끝내지 못했으면 이미지 완료라고 말하지 않는다. 다음 세션은 이미 승인된 해시를 유지하고 누락·불합격 파일만 이어서 처리한다.

### 11.2 다음 코드 세션용 인계 문장
```text
이미지 작업 상태는 handoff/art/ASSET_READY.json에 기록돼 있다.
ready=true 여부만 믿지 말고 세 문서 해시, manifest 해시, 필수 54개 파일,
실제 PNG 해시·크기·알파·검수 기록을 다시 검증하라.
모든 항목을 통과한 뒤 02_CODE_GENERATION_INSTRUCTIONS.md를 실행하라.
불일치가 있으면 게임 코드 개발을 시작하지 말고 누락/불일치 ID를 보고하라.
이미지 파일명을 추측하거나 placeholder를 끼워 넣어 통과시키지 마라.
```

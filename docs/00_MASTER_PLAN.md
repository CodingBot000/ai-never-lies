## 1. 제작 범위와 승인 게이트

### 1.1 반드시 포함할 범위
본작 첫 사건을 시작 화면부터 사건 기록 화면까지 완주 가능하게 만든다. 조사 허브, 포인트앤클릭 조사, 문서·영상·로그 열람, 증언 단위 추궁, 여러 증거의 조합 반박, 시간축, 실행 경로, 코드 변경 비교, 시험 커버리지, 반사실 비교, 인과판, 보고서 작성, 선택 면담, 세이브·로드, 팁·테스트 지원을 포함한다. **첫 심문만 만드는 수직 슬라이스로 범위를 줄이지 않는다.** 개발 중 작은 구간을 먼저 검증하는 것은 가능하지만 최종 납품은 ep01 전체다.

확정 콘텐츠 수는 서사 씬 **43개**, 명시적 퍼즐 **20개**, 증거 **36개**, 런타임 일러스트 **54개**다. 서사 씬은 Unity `.unity` 파일과 다르다. 데이터로 전환되는 장면이며 Unity 씬을 43개 만드는 요구가 아니다. 주연 관계자 7명, 위원장·유족 2명, 피해자는 증거 사진으로 등장한다. 조사관은 1인칭이며 별도 초상이 없다.

첫 플레이 목표는 120~180분의 읽기·조사 경험이지만 추정값이다. 시험 결과가 더 짧으면 시간을 채우기 위한 반복 클릭이나 불필요한 대사로 늘리지 않는다. 충분한 이해·추리·감정 곡선이 있는지 먼저 평가한다. 타이머와 제한 시간은 없다.

### 1.2 이번 범위에서 제외
3D 자유 이동, 실시간 차량 물리 시뮬레이터, 실제 자동차 프로토콜, 실제 의료·법률 자문, 음성 녹음·성우, 온라인 계정·DB·서버, 멀티플레이, 결제, 광고, 업적 서비스 연동, 런타임 AI, 두 번째 사건, 전면 모바일 세로 UI, 콘솔 인증은 제외한다. 음악·효과음 파일은 이번 **이미지 선행 완료**의 차단 요소가 아니다. 소리 없이도 모든 사건을 이해하고 해결할 수 있어야 한다.

### 1.3 문서의 우선순위
사용자의 명시적 최신 변경 지시 → 이 마스터의 사건·ID·상태·정답 → 이미지 지시문의 아트 규격 → 코드 지시문의 구현 방식 순이다. 코드가 어렵다는 이유로 사건 정답·진행 조건을 바꾸지 않는다. 아트가 예쁘다는 이유로 증거 사실을 바꾸지 않는다. 충돌이 생기면 `handoff/CHANGELOG.md`에 충돌·영향·해결을 남기고 동일 버전의 세 문서를 수정한다.

자산 ID·증거 ID·씬 ID·퍼즐 ID는 출시 이후 이름을 바꾸지 않는 영구 키로 취급한다. 화면에 표시하는 한국어 이름과 분리한다. ID 재사용 금지. 수정 시 삭제 대신 deprecated 또는 마이그레이션을 사용한다.

## 2. 게임 정체성과 사건 정본

### 2.1 핵심 경험
“사람을 못 봤다”는 설명에서 출발해, **판단 → 명령 조정 → 실행 → 운영 승인 → 검증·관리 결정**의 경계를 복원한다. 반전은 새 악당을 계속 만드는 것이 아니라, 이전에 알고 있던 사실의 의미를 더 정확하게 만드는 방식이다. 플레이어의 가장 중요한 행동은 증거를 선택해 **특정 주장과 연결하는 일**이다.

기본 루프는 조사 → 인물 대화 → 증거 열람 → 주장 선택 → 근거 제출 → 새 쟁점 → 재구성이다. 모든 중요한 반전은 플레이어가 최소 하나의 검증 행동을 완료한 뒤에만 공개한다. 캐릭터가 결론을 먼저 말하고 플레이어가 정답을 반복 클릭하는 방식으로 만들지 않는다.

### 2.2 제목 해석과 표현 금지
제목은 수사극의 역설적 문구이지 “현실의 AI는 거짓말을 못 한다”는 기술 설명이 아니다. 로그는 누락·변조·잘못된 계측·잘못된 해석 가능성이 있는 자료다. 본 사건에서는 보존·시계·독립 기록 대조를 통해 **주장에 필요한 범위**를 확인한다. 해시가 같다고 내용 전체가 진실이라고 말하지 않는다.

“AI가 피해자를 살리려고 했다”, “모델이 선했다”, “AI가 정답을 냈으니 시스템 전체가 무죄”, “모두의 책임이므로 아무 책임도 없다”는 결론을 사용하지 않는다. 최종 대사는 **적시에 기록된 제동 요청과 그것이 변경된 경로**를 말한다. 이야기 속 제동 조정 정책은 결함이 있는 가상 설계다. 현실 자동차의 일반적·표준적 안전 정책이라고 설명하지 않는다.

### 3.1 책임을 표현하는 방식

플레이어가 틀린 결론을 선택할 때 즉시 캐릭터가 범죄자로 변하거나 체포되는 비정본 엔딩은 만들지 않는다. 증거가 부족한 주장은 보고서 초안에서 수정하게 한다. 종합적으로 정확한 기술 결론은 하나이며, 마지막 표현의 우선순위와 선택 면담만 달라진다.

### 4.2 애니메이션 범위
배경 전환 150~300ms, 인물 표정 전환 100~180ms의 단순 페이드. 입모양 프레임·리깅·Live2D·3D 모델은 필요하지 않다. 중요한 반박은 짧은 패널 이동과 강조선으로 표현하되 대형 “이의 있음” 복제 연출에 의존하지 않는다. 빗방울·플래시·카메라 흔들림은 꺼도 정보가 사라지지 않는다. 자동 재생은 기본 OFF; 빠른 글자 출력은 옵션이다.

로그를 영화식 해킹 화면처럼 자동 스크롤시키지 않는다. 이용자가 선택한 시점이 바뀌지 않게 한다. 한 번에 모든 UI를 펼치지 않고 문맥에 필요한 도구만 연다. 기존 콘셉트 이미지의 다중 패널 구성은 화면 유형의 참고이지 실제 게임을 항상 세 칸으로 합치는 요구가 아니다.

### 4.3 조작과 실수 방지
마우스 클릭과 키보드 탐색을 지원한다. 카드 드래그는 선택 기능이며 **카드 클릭→슬롯 클릭**으로 동일하게 해결 가능해야 한다. Enter는 포커스된 버튼 확인, Space는 대화 다음, Esc는 가장 위 모달 닫기/메뉴. 텍스트 입력 칸이 포커스될 때 단축키가 작동하지 않아야 한다. 모달 뒤 버튼에 클릭이 전달되지 않는다. 더블클릭과 빠른 연타로 증거 두 번 지급·노드 두 번 진입이 발생하면 실패다.

화면 우상단에 `현재 목표 / 증거 / 수첩 / 팁 / 메뉴`를 항상 제공하되 영상 전면 컷신은 메뉴 버튼으로 대체할 수 있다. 테스트 빌드에서는 팁 접근이 숨겨진 단축키에만 의존하지 않는다.

### 4.4 증거를 읽는 세 단계
목록에서 발견→본문에서 열람→특정 주장과 연결하여 사용을 구분한다. 획득했다고 읽은 것으로 처리하지 않는다. 열람했다고 해당 결론이 자동 입증되지 않는다. 서로 다른 자료가 같은 내용을 보이면 복수 정답 조합을 명시한 경우에만 대체 근거로 인정한다. `evidenceSets`는 최소 충분 근거 집합이다. 최대 3개까지의 보유 자료 선택에 그 집합이 포함되면 통과한다. 추가로 고른 보유 자료 때문에 정답을 오답으로 바꾸지는 않으며, 성공 후 실제 핵심 근거만 강조한다. 다른 증언을 선택했거나 필수 근거 일부만 있는 경우는 통과하지 않는다. 미래의 증거 이름·썸네일·정답을 잠금 목록에서 누출하지 않는다.

## 6. 전체 진행 그래프와 씬별 대사

### 6.1 큰 흐름
```text
s000 → s010 → s020
  → s100 {s110, s120, s130 자유 순서 / 전부 필수}
  → s140 → s150 → s160 → s170
  → s200 {s210, s220, s230 자유 순서 / 전부 필수}
  → s240
  → s300 {s310 → s320 → s330}
  → s340
  → s400 {s410→s411, s420, s430 / 네 씬 필수}
  → s440 → s450 → s460
  → s500 {필수 s510+s540 / 선택 s520+s530}
  → s550 → s600 → s610 → s620 → s630 → s640 → s650
  → s700 → s710 → 타이틀 또는 새 리플레이 슬롯
```

중괄호 조사 뒤에는 해당 허브로 돌아온다. 잠긴 목적지는 이유를 표시한다. 필수 조사 완료 후에도 사용자가 “다음 단계”를 눌러 이동하며 자동으로 남은 선택 조사를 닫지 않는다. s410→s411은 직접 연결할 수 있고 허브로 돌아갔다 다시 s411을 열어도 동일 상태다.

### 6.2 대사 단계 규칙 — 정답 선공개 방지
각 씬의 `상호작용 삽입 위치`가 있는 경우, 지정된 L번호까지 도입을 재생한 뒤 퍼즐/심문을 실행한다. 그 이후 대사는 **성공 후**에만 재생한다. `0`이면 도입 대사 없이 자료·목표를 보여주고 바로 상호작용한다. 증언·추궁 대사는 7장에서 별도로 재생한다. 성공 반응의 일부가 본문 후반 대사와 겹치면 본문 후반에서 한 번만 재생하도록 동일 textId를 참조한다. 정답을 먼저 읽어주는 두 번 재생은 금지한다.

퍼즐이 없는 씬은 대사 사이의 문서 열람·선택을 해당 `플레이` 조건에 맞춰 삽입한다. s530의 자료 수신, s700의 답변 우선순위는 9장 분기 대사를 사용한다. 인물 한 장을 바꿔 배치하는 것은 가능하지만 대사 내용이나 사실을 즉석에서 생성하지 않는다.

초기 s160/p05에서는 인식·요청·약한 제동·강한 제동·충돌 다섯 사건만 공개한다. 제동 조정기의 개입 시각과 이유는 ev10을 얻은 뒤 공개한다. 정본 전체 시간축이나 개발용 정답 데이터가 있다는 이유로 아직 입수하지 않은 이벤트를 플레이어에게 표시하지 않는다.

## 7. 심문 증언과 추궁 반응

증언은 문장 단위로 선택된다. `추궁`은 새 설명을 열지만 자의적으로 증거를 지급하지 않는다. `제시`는 선택된 statementId와 보유 증거 집합으로 판정한다. 여러 증거를 제출할 때 선택 순서는 무관하지만 조합의 의미는 동일해야 한다. 제출 뒤 원래 증언 위치와 선택 스크롤을 유지한다.

정답 증언 외에 관련 자료를 제시했을 때도 일반 “틀렸습니다” 대신 범위 오류를 설명한다. 같은 정답 증거를 다른 증언에 제시한 경우 `맞는 자료지만 지금 선택한 주장과 직접 충돌하지 않습니다. 어떤 주장을 반박하는지 다시 고르십시오.`를 표시한다. 미래 획득 자료를 개발자 콘솔로 넣은 상태는 일반 유저 테스트로 간주하지 않는다.

### 7.1 공통 오답·부분 정답 반응 우선순위
1. 제출 조건 미충족: “먼저 증언과 보유 자료를 선택하세요.” 상태 변화 없음.
2. 자료의 출처 미확인: “자료의 생성 시점과 대상이 이 사건과 연결되는지 확인해야 합니다.” 관련 자료를 열 수 있는 버튼만 제공.
3. 정답 자료 일부만 제출: 퍼즐의 부분 정답 대사. 선택 자료 유지. 오답 패널티 없음.
4. 맞는 자료·다른 주장: 위의 범위 안내. 증언 목록 유지.
5. 무관한 자료: “이 자료만으로 지금 주장을 반박할 수 없습니다.” 상세 퍼즐 오답이 있으면 우선.
6. 확정한 사실의 과잉 해석: “그 사실에서 해당 결론까지 이어지는 근거가 부족합니다.” 논리 범위를 설명.

체력·생명·재판 패배 카운트는 없다. 실패는 사고 진상을 영구히 놓치는 분기를 만들지 않는다. 반복 오답은 2회 후 팁 버튼에 점 표시, 4회 후 “정답 확인” 선택지를 제안하되 자동으로 열지는 않는다.

### 9.2 주된 엔딩 결과
위원회는 기술적 원인과 기여 요인을 채택하고 관련 행위·증거를 별도 책임 판단 절차에 넘긴다. 현장 즉시 체포·형량·손해배상액을 게임이 확정하지 않는다. 권고는 네 축이다: 위험 차량 운행 해제 통제, 조건부 승인 이행 확인, 결함·운영 예외를 포함한 조합 시험, 자료 출처의 명확한 공개. 효과가 현실에서 입증된 것처럼 “이제 사고는 다시 안 난다”는 문구를 쓰지 않는다.

### 10.1 최종 인과판 노드
| 노드 ID | 표시명 | 종류 | 주요 근거 |
| --- | --- | --- | --- |
| n_fault | 후방 센서 결함 | physical | ev15, ev17, ev14 |
| n_false_rear | 실재하지 않는 후방 객체 입력 | physical | ev12, ev13, ev14 |
| n_override | 재발 경고 뒤 운행중지 해제 | operational | ev17, ev18, ev19, ev31 |
| n_onroad | 결함 상태로 도로에 투입 | operational | ev01, ev18 |
| n_gate_removed | 배포본의 건강정보 확인 제거 | software | ev22, ev27 |
| n_trusted_rear | 결함 입력이 제동 제약 근거로 채택 | and | ev10, ev32 |
| n_brake_limit | 긴급제동 요청 강도 제한 | and | ev06, ev08, ev10 |
| n_collision | 제동 제한이 충돌 경로에 기여 | outcome | ev33 |
| n_request | 적시에 기록된 긴급제동 요청 | signal | ev06, ev07 |

p17의 인과 간선 7개는 다음과 같다. 시간순 줄세우기가 아니다. `n_trusted_rear`는 유령 객체 입력과 검증 제거가 함께 필요한 AND 결합이다. `n_brake_limit`는 그 입력과 실제 도로 투입이 함께 결합한 사건 내 결과다. AND는 이 사건 모델에서 요구되는 조건 묶음이지 실제 시스템의 모든 충분·필요조건을 형식 증명했다는 뜻이 아니다.

```json
{
  "causalEdges": [
    [
      "n_fault",
      "n_false_rear"
    ],
    [
      "n_override",
      "n_onroad"
    ],
    [
      "n_false_rear",
      "n_trusted_rear"
    ],
    [
      "n_gate_removed",
      "n_trusted_rear"
    ],
    [
      "n_trusted_rear",
      "n_brake_limit"
    ],
    [
      "n_onroad",
      "n_brake_limit"
    ],
    [
      "n_brake_limit",
      "n_collision"
    ]
  ],
  "signalEdges": [
    [
      "n_request",
      "n_brake_limit"
    ]
  ]
}
```

`n_request→n_brake_limit`는 청록색 신호선이며 “정상 판단이 잘못”이라는 책임선이 아니다. 실제 도로의 보행자 존재는 사건 조건으로 주석 처리하며 피해자를 원인 책임 노드에 넣지 않는다. KPI와 관리 책임은 p18·p20의 별도 레이어다. 사후 발표 왜곡은 충돌로 향하는 원인 화살표를 가질 수 없다.

각 간선의 충분 근거 집합은 p17 정답 모델의 `proofRequirements`가 정본이다. 인과선 7개와 신호선 1개 모두 근거가 필요하며, 해당 간선에 정해진 최소 집합을 연결한다. 예: 결함→유령 입력 ev14+ev17; 해제→도로 투입 ev18+ev01; 검증 제거→신뢰된 결함 입력 ev22+ev27+ev32; 제동 제한→충돌 기여 ev08+ev33. 같은 자료는 서로 다른 간선에 재사용할 수 있고 소비되지 않는다. 자료가 입증하는 범위를 넘어선 간선에는 이유와 함께 수정 안내를 제공한다.

### 10.3 반사실 재구성 수치
이 게임은 실제 차량 물리 시뮬레이터를 구현하지 않는다. 다음은 작품 내부의 일관성을 위한 작성된 운동학 예제이며, 보고서 가정을 UI에 함께 보여준다. 제동 요청값 -8.1을 곧바로 노면 가속도로 대입하지 않는다.

```text
v0 = 47 / 3.6 = 13.055555... m/s
actuator_delay = 0.08 s
weak_duration = 1.28 s ; weak_deceleration = 2.0 m/s²
strong_duration = 0.46 s ; measured_strong_deceleration = 6.2 m/s²

historical_distance
 = v0 * 0.08
 + (v0 * 1.28 - 0.5 * 2.0 * 1.28²)
 + ((v0 - 2.0 * 1.28) * 0.46 - 0.5 * 6.2 * 0.46²)
 = 20.28915111 m ≈ 20.29m

historical_impact_speed
 = (v0 - 2.0 * 1.28 - 6.2 * 0.46) * 3.6
 = 27.5168 km/h ≈ 27.52km/h

full_brake_stopping_distance
 = v0 * 0.08 + v0² / (2 * 6.2)
 = 14.79021306 m ≈ 14.79m
```

노면 감속 가정 5.6~6.8m/s² 범위를 사용하면 정지거리 약 13.58~16.26m다. 시야·타이어·수막·보행자의 후속 이동 등을 완전히 모델링하지 않는다. 화면에는 “이 보고서의 입력·노면 가정에서 충돌 회피 가능성 뒷받침”으로 표시한다. 생존율·사망 확률을 계산하지 않는다. p16의 배차 차단 조건에서는 주행 그래프를 재생하지 않고 “운행이 발생하지 않음”이라고 표시한다.

## 11. 상태·저장·힌트·테스트 계약

### 11.1 상태의 세 층
**정적 콘텐츠:** 인물·씬·대사·증거·퍼즐·정답·힌트·간선·아트 ID. JSON에서 읽고 런타임에 수정하지 않는다.
**진행 상태:** 현재 씬/단계/대사, 획득·열람 증거, 방문·완료 씬, 해결 퍼즐, 주제 읽음, 선택 분기, 인과판 초안, 보고서 초안, 힌트 사용 기록.
**일시 UI 상태:** 포커스, 열린 패널, 비교 시점, 스크롤, 선택된 증거. 필요한 것은 스냅샷에 저장하고 마우스 좌표·애니메이션 중간값은 저장하지 않는다.

플래그 문자열을 여러 컴포넌트에서 직접 고치지 않는다. `GameCommand → Validate → Reduce → Events → Save checkpoint → Render` 한 경로로 처리한다. 증거 지급은 집합 삽입이며 같은 ID를 다시 얻어도 수량이 늘지 않는다. 문서 열람, 퍼즐 해결, 씬 완료는 다른 상태다.

### 11.2 장면 단계
`entering → pre_dialogue → interaction → post_dialogue → ready_to_exit → completed`를 사용한다. 허브는 `hub_active`로 별도 처리한다. 해결 전 post_dialogue 접근은 오류다. 대화를 빠르게 출력하는 것은 가능하지만 required interaction을 건너뛰지 않는다. 디버그 점프는 완전한 유효 픽스처를 로드하는 별도 기능이며 정상 진행의 solved 플래그 조작으로 흉내내지 않는다.

### 11.3 저장 요구
자동저장은 증거 획득, 퍼즐 성공, 중요한 분기, 장면 종료에서 발생한다. 수동 슬롯 최소 3개와 자동 슬롯 1개. 이어하기는 가장 최신의 **유효한** 저장을 선택한다. 손상되면 백업 복원을 안내하고 조용히 초기화하지 않는다. 다른 버전·알 수 없는 ID는 마이그레이션 또는 호환불가 안내 후 원본 보존이다.

저장에는 `saveSchemaVersion`, `contentVersion`, `artManifestSha256`, `slotId`, `savedAtUtc`, `currentSceneId`, `phase`, `dialogueCursor`, 획득·열람·완료 집합, 퍼즐별 초안, 선택지, 힌트 레벨·자동해결 여부가 포함된다. 조사 허브의 자식 완료 여부도 복원한다. 전체 상태를 자의적으로 재추론해 다른 대사를 보여주지 않는다. 장면 재진입 보상은 idempotent여야 한다.

### 11.4 팁 버튼
매 장면 팁은 6장 장면 팁으로 작동한다. 퍼즐 도중에는 현재 퍼즐의 H1/H2/H3를 사용한다. H1=방향, H2=찾을 자료, H3=정확한 정답. 각 레벨은 개별 버튼으로 열며 앞선 힌트를 억지로 여러 번 눌러야 정답이 나오는 구조를 피한다. 퍼즐이 아닌 대화에서는 “다음 대사”, 허브에서는 “다음 필수 조사”, 자료창에서는 “확인할 영역”을 안내한다.

테스트 빌드의 `정답 행동 실행`은 선택한 퍼즐의 유효 사용자 행동 목록을 실행한다. 누락 증거가 있으면 그 증거를 몰래 지급하지 않고 필요한 장면/자료 인계로 안내한다. 성공 후 대사·이벤트·저장·힌트 이력이 정상 경로와 동일해야 한다. 시험 지원이 사용됐다는 표시만 남기고 결말을 벌점으로 변경하지 않는다.

공개 배포에서 H1~H3를 유지하는 것은 허용하되, `정답 행동 실행`, 임의 점프, 전체 증거 지급, 상태 편집 패널은 `ANL_TEST_TOOLS` 및 개발 빌드에만 포함한다. “테스트 지원 끄기”는 코드 경로가 제거된 릴리스 검증으로 확인한다. 클라이언트에 정답 데이터가 있다는 사실을 보안적으로 숨길 수 있다고 주장하지 않는다.

### 11.5 빠른 검증 모드의 한계
정답 행동 실행으로 완주했다고 일반 플레이를 검증한 것은 아니다. 실제 클릭 완주, 오답 후 복귀, 모든 필수 지점에서 저장·종료·복귀, 조사 순서 변경, 키보드만 사용하기를 별도로 실행한다. 팁은 해결을 돕는 도구이며 테스트 누락을 가리는 장치가 아니다.

다른 배경은 각 씬의 background ID를 사용한다. `bg_crosswalk_rain`은 s010 사고 전 외부 장면의 짧은 컷과 s110 현장 비교 탭에서 사용한다. 이로써 배경·표정·사건 이미지 54개의 실제 사용 위치가 정의된다. 사용 여부 검사는 콘텐츠 참조와 cue 표를 합친 집합을 기준으로 한다.

### 12.2 아트 인계 증빙
`manifest.plan.json`은 이 목록을 옮긴 계획이며 `planned` 상태로 시작한다. `manifest.lock.json`은 실제 검사한 파일의 크기·해시·알파·검수 결과·단서 영역 좌표를 담은 완료본이다. `ASSET_READY.json`은 검증 통과한 잠금본의 해시를 가리킨다. 존재하지 않는 파일을 완료로 기재하거나 예시 SHA를 복사하면 안 된다. 미완료일 때는 `ready=false`와 누락 ID를 명시한다.

선택 면담 장면의 이미지도 이번 전체 사건 아트 범위에 포함되므로 54개 전부 완료 후 코드를 시작한다. 단, 접촉시트·검수 스크린샷은 파생 산출물로 개수에 포함하지 않는다. 폰트·오디오·기본 UI 도형은 생성 이미지 개수에 포함하지 않는다.

### 14.3 ev22 변경 비교 — 화면용 원문
다음은 **작품 속 결함 있는 정책을 설명하는 의사코드**다. 실제 차량 소프트웨어 구현이나 안전 표준이 아니다. 이 게임에 차량 제어 코드를 실행하는 기능을 만들지 않는다. 고정 텍스트로 보이고 블록을 클릭한다.

변경 전 v3.4:
```text
[imminent_override]
if independent_imminent_collision:
    return emergency_request  // 후방 제약보다 우선

[health_snapshot_validation]
health = await sensor_health_snapshot
if health is missing or health.valid == false or health.age_ms > 100:
    return emergency_request  // 신뢰할 수 없는 후방 입력을 제한 근거로 쓰지 않음

[rear_risk_arbitration]
if rear_risk_score > 70:
    return limited_request(-2.0)
return emergency_request
```
변경 후 v3.5:
```text
[imminent_override]
if independent_imminent_collision:
    return emergency_request

[health_snapshot_validation]
// 제거됨: 운행 진단이 결함차 배차를 막는다는 전제로 대체

[rear_risk_arbitration]
if rear_risk_score > 70:
    return limited_request(-2.0)
return emergency_request
```

21ms는 위 health bridge의 동기화 경로를 포함한 작품 내 측정 차이다. `valid == false`나 `age_ms > 100` 비교 자체의 비용으로 표시하지 않는다. 후방 위험 점수가 높다는 이유로 전방 보행자 제동을 줄이는 정책도 본 사건에서 검토할 **설계 결함**이다. “안전을 위한 정상 규칙”이라고 교육하지 않는다.

T-0.54의 독립 충돌임박 플래그는 후방 위험 분기보다 높은 우선순위이며, 해당 요청이 T-0.46에 실제 강한 제동으로 이어진다. 제약이 마지막에 이유 없이 풀리거나 최종 순간 브레이크 고장이 저절로 고쳐졌다는 장면을 만들지 않는다. 두 시점 차이 80ms는 이 작품의 액추에이터 지연 픽스처다.

값들은 재생 프레임률이나 초 단위 반올림에서 역산하지 않는다. source / relativeTimeMs / payload를 갖는 정적 JSON을 만들고 동일 데이터가 모든 로그·타임라인·최종 재생에 공급된다. unknown field를 임의로 채우지 않는다. 전방위험 91.2/100과 후방위험 71/100은 서로 다른 모델 점수이며 두 숫자를 직접 비교해 윤리적 선택의 우열을 판단하지 않는다. health.valid와 classScore는 서로 다른 개념이다.

### 14.5 정적 이미지로 영상 증거를 보여주는 계약
이번 아트 범위에는 동영상 파일이나 프레임 시퀀스가 없다. ev03·ev05·ev12·ev13의 “영상”은 **보존 영상에서 추출한 기준 프레임+시간 주석**을 읽는 인터페이스로 구현한다. 원본 스트림 전체를 재생한다고 거짓 표시하지 않는다. 탭 제목은 `영상 기록 / 기준 프레임`이며 재생 버튼 설명은 `기록 주석 순서 재생`이다.

전방·후방·차내·CCTV 기준 이미지를 임의로 움직여 가짜 실제 주행 영상을 만들지 않는다. 선택 가능한 시간 마커에서 이미지를 유지하고 코드 오버레이·설명만 바꾼다. 이미지가 매 시점의 실제 프레임이라는 오해를 막기 위해 항상 “선정된 기준 프레임, 시간별 기록은 오른쪽 패널”을 표시한다. 객체 이동이나 거리의 정밀 판정은 ev03 사고도·ev09 시계 보정·ev12/13 판독 기록을 근거로 한다. 비·경고 점멸은 분위기 연출일 뿐 정답 판정 근거가 아니다.

이 선택은 이미지 선행 제작의 범위를 54개로 고정하기 위한 제품 범위다. 향후 실제 영상 클립을 도입한다면 별도 아트 계약 버전과 검수 항목을 추가해야 하며, 코드 세션이 뒤늦게 새 영상을 요구해 개발을 막지 않는다.

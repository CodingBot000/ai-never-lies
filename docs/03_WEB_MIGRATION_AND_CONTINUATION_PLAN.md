- 문서 ID: `ANL-WEB-MIGRATION`
- 문서 버전: `1.0.0`
- 작성 기준일: `2026-09-14`
- 적용 범위: Episode 01 전체 개발
- 결정 상태: **확정 — Unity 사용 금지, 웹 기반으로 이전 및 개발 계속**

## 0. 최상위 결정과 문서 우선순위

이 프로젝트의 최종 실행 환경은 **웹 브라우저**다. 지금부터 Unity 기반 개발은 즉시 중단하며 다시 시작하지 않는다.

이 문서는 기존 세 문서에 남아 있는 Unity 관련 지시보다 우선한다. 기존 문서가 개정되기 전까지 충돌하는 항목은 모두 이 문서의 웹 기준으로 해석한다.

우선순위는 다음과 같다.

1. 사용자의 최신 명시적 지시
2. 본 웹 전환·연속 개발 작업계획서
3. 개정된 `00_MASTER_PLAN.md`
4. `01_IMAGE_GENERATION_INSTRUCTIONS.md`의 이미지 콘텐츠·규격 계약
5. 개정된 `02_CODE_GENERATION_INSTRUCTIONS.md`

## 1. 절대 준수사항

### 1.1 Unity 절대 사용 금지

앞으로 다음 작업을 수행하지 않는다.

- Unity Editor 실행 또는 batchmode 실행
- Unity Hub, UPM 패키지, Unity 라이선스, Unity Cloud 사용
- Unity WebGL을 포함한 Unity 빌드 생성
- `.unity` 씬, Prefab, ScriptableObject, MonoBehaviour, uGUI, TextMesh Pro 기반 신규 구현
- 기존 Unity 코드에 기능 추가, 버그 수정, 화면 추가 또는 콘텐츠 추가
- 웹 개발을 위해 Unity 런타임이나 Unity 생성물을 중간 계층으로 사용하는 방식
- Unity 프로젝트를 웹게임 완성본 또는 기준 구현으로 계속 유지하는 병행 개발

기존 Unity 소스는 웹 이전이 끝날 때까지 **읽기 전용 참고 자료**로만 사용할 수 있다. 기존 동작과 테스트 의도를 확인하는 것 외에는 실행·수정·확장하지 않는다.

### 1.2 웹 이전은 범위 축소가 아니다

웹 버전이 현재 Unity 구현과 비슷하게 동작하는 시점은 이전 완료일 뿐, 프로젝트 최종 완료가 아니다.

웹 이전이 완료되면 별도 승인 대기나 재계획 단계로 멈추지 않고, 기존 마스터 플랜에서 아직 구현되지 않았거나 검증되지 않은 작업을 모두 웹 기반으로 이어서 개발한다.

기존 Unity 구현에 누락, 임시 처리, 빈 화면, 미검증 동작 또는 잘못된 동작이 있으면 그대로 복제하지 않는다. 마스터 플랜의 정본 콘텐츠와 완료 조건을 기준으로 웹에서 올바르게 구현한다.

### 1.3 전면 삭제 금지

현재 작업물을 먼저 삭제하고 처음부터 다시 만들지 않는다. 다음 자산은 웹에서도 재사용한다.

- 런타임 이미지 54개와 아트 manifest
- Episode 01 콘텐츠 JSON
- 장면·증거·퍼즐·대사·분기 ID
- 순수 C#으로 작성된 상태 전이·조건·퍼즐 판정의 동작 규칙
- 기존 단위 테스트와 전체 진행 테스트의 시나리오 및 기대 결과
- 콘텐츠·아트 검증 스크립트와 검증 기준
- 사용 권한이 확인된 한글 폰트와 라이선스 문서

Unity 전용 파일은 웹 동등성 검증이 끝난 뒤 제거한다.

## 5. 작업 단계와 승인 게이트

### W0 — 현 상태 보존과 지시문 정정

작업:

1. 현재 추적 대상 파일을 Git 기준선 커밋으로 보존한다.
2. 현재 Unity 소스의 마지막 상태를 식별할 수 있는 태그를 남긴다.
3. `00_MASTER_PLAN.md`의 Unity/C#/uGUI/데스크톱 우선 문구를 웹 기준으로 개정한다.
4. `02_CODE_GENERATION_INSTRUCTIONS.md`를 React/TypeScript/Vite 기준의 코드 개발 지시문으로 전면 개정한다.
5. `01_IMAGE_GENERATION_INSTRUCTIONS.md`의 Unity pivot·임포트 표현을 웹 좌표·asset URL 기준으로 개정한다.
6. 세 문서가 바뀌면 실제 바이트 해시를 다시 계산해 `ASSET_READY.json`의 문서 해시를 갱신한다. 이미지 바이트가 바뀌지 않았다면 이미지 재생성은 하지 않는다.
7. `handoff/CHANGELOG.md`에 Unity→Web 변경 이유와 영향을 기록한다.

통과 기준:

- 세 문서 어디에도 Unity를 실행하거나 사용하라는 유효 지시가 없다.
- 웹 기술 기준과 본 문서가 서로 충돌하지 않는다.
- 기존 작업의 보존 커밋이 존재한다.
- `ASSET_READY`의 문서 해시가 개정 문서와 일치한다.

### W1 — 웹 프로젝트 기반 구성

작업:

1. `web/`에 React + TypeScript + Vite 프로젝트를 생성한다.
2. lint, typecheck, unit test, browser test, production build 명령을 구성한다.
3. 전역 디자인 토큰, 한글 폰트, 기본 접근성 스타일, 오류 경계를 구성한다.
4. 개발·릴리스 모드를 분리하고 테스트 전용 기능이 릴리스에서 노출되지 않게 한다.
5. 빈 앱이 아니라 타이틀 화면과 기본 내비게이션이 실제 브라우저에서 렌더링되는 상태까지 만든다.

통과 기준:

- 개발 서버가 브라우저에서 열린다.
- TypeScript, lint, unit test, production build가 모두 성공한다.
- 데스크톱과 모바일 폭에서 빈 화면·오버플로·런타임 오류가 없다.
- Unity 실행 없이 모든 검증이 가능하다.

### W2 — 콘텐츠와 아트의 엔진 독립 이전

작업:

1. 콘텐츠 JSON을 `content/ep01/`로 복사하고 이를 새 정본 위치로 지정한다.
2. 콘텐츠 스키마를 TypeScript 타입으로 선언하고 런타임 검증을 추가한다.
3. 54개 이미지와 manifest를 웹 정적 자산 위치로 동기화하는 스크립트를 만든다.
4. asset ID→URL 카탈로그를 생성하고 파일명 추측 방식의 로딩을 금지한다.
5. 아트 크기, RGBA, 해시, 누락, 중복 검사를 웹 경로 기준으로 실행한다.
6. 기존 Python 콘텐츠 검증 도구가 Unity 경로에 의존하지 않도록 수정한다.

통과 기준:

- 콘텐츠 수가 씬 43, 증거 36, 퍼즐 20과 일치한다.
- 이미지 54개가 모두 asset ID로 조회된다.
- 브라우저 네트워크 로그에 404 이미지·JSON 요청이 없다.
- `Game/` 폴더를 참조하지 않고 콘텐츠·아트 검증이 통과한다.

### W3 — 핵심 게임 로직 TypeScript 포팅

포팅 순서:

1. 콘텐츠 DTO와 인덱스
2. `GameState`와 저장 스냅샷
3. 조건 판정기
4. 명령과 결과·도메인 이벤트
5. `CommandDispatcher`
6. 20개 퍼즐 판정기
7. 힌트 서비스와 테스트 지원 플래너
8. 저장·로드·자동저장·손상 복구

원칙:

- 기존 C#의 클래스 이름을 기계적으로 복사하는 것이 아니라 동작 계약을 TypeScript로 옮긴다.
- 동일한 입력 상태와 명령은 동일한 결과 상태를 만들어야 한다.
- UI가 상태를 직접 수정하지 않고 항상 명령 처리기를 통한다.
- 퍼즐 정답을 컴포넌트 내부에 중복 하드코딩하지 않는다.
- 저장 데이터에는 DOM, React 컴포넌트, 함수 또는 브라우저 객체를 넣지 않는다.

통과 기준:

- 기존 EditMode 테스트의 의미를 옮긴 Vitest 테스트가 모두 통과한다.
- 43개 장면과 20개 퍼즐의 참조 무결성이 통과한다.
- 필수·선택 분기 조합과 저장 복원 경로가 통과한다.
- Unity 코드 실행 없이 모든 판정 결과를 재현한다.

### W4 — 현재 구현 범위의 웹 화면 이전

화면 구현 순서:

1. 타이틀·경고·새 게임·이어하기
2. 대화·인물 표정·배경 레이어
3. 조사 허브와 포인트앤클릭 조사
4. 증거 열람과 region 오버레이
5. 증언 추궁과 증거 제시
6. 퍼즐 공통 호스트와 유형별 위젯
7. 시간축·비교·배치·연결·인과판
8. 보고서 작성
9. 설정·힌트·세이브·로드
10. 엔딩·사건 기록
11. 개발 전용 진단 패널

UI 구현 전에 기존 이미지와 콘텐츠를 기준으로 웹용 디자인 명세를 만든다. 타이틀, 대화, 조사, 증거, 퍼즐, 보고서, 모바일 상태를 포함해야 하며 사용자의 승인을 받은 디자인을 구현 기준으로 고정한다.

통과 기준:

- 기존 Unity에서 구현된 모든 사용자 행동이 웹에서 가능하다.
- 텍스트가 이미지에 구워지지 않고 실제 HTML로 렌더링된다.
- 키보드·마우스·터치 입력이 동일한 게임 명령으로 연결된다.
- 1280×720, 1920×1080, 2560×1440 및 모바일 폭에서 핵심 콘텐츠가 잘리지 않는다.
- 관련 브라우저 콘솔 오류가 없다.

### W5 — 이전 완료 판정

웹 이전 완료는 다음 조건을 모두 만족할 때만 선언한다.

- 기존 Unity 구현의 기능 목록이 웹에서 동등하거나 더 올바르게 동작한다.
- 기존 테스트 시나리오가 웹 단위·통합·E2E 테스트로 대체됐다.
- 기존 콘텐츠·세이브·퍼즐 규칙이 웹에서 검증됐다.
- Unity 폴더를 참조하지 않고 웹 production build가 성공한다.
- 시작 화면부터 기존 구현이 도달했던 마지막 화면까지 실제 브라우저 입력으로 진행된다.

이 게이트 통과는 프로젝트 완료가 아니다. 통과 즉시 W6을 시작한다.

### W6 — 기존 미완료 작업의 웹 기반 연속 개발

W5 직후 마스터 플랜 전체와 현재 웹 구현을 대조해 `WEB_IMPLEMENTATION_STATUS.md`를 작성한다. 모든 항목을 `DONE`, `PARTIAL`, `MISSING`, `NOT_RUN`으로 표시하고 근거 파일·테스트를 연결한다.

그다음 다음 범위를 웹에서 계속 구현한다.

- 43개 전체 서사 씬
- 36개 증거의 원문·요약·출처·한계와 획득 조건
- 20개 전체 퍼즐과 부분 정답·오답·복귀 동작
- 모든 필수·선택 분기와 엔딩 반영

규칙:

### W8 — Unity 제거

W5 웹 이전 완료와 W6 전체 구현 완료, W7 브라우저 검증이 모두 통과한 뒤 Unity 파일을 제거한다.

제거 대상:

- `Game/Library/`, `Game/Temp/`, `Game/Logs/`, `Game/UserSettings/`
- `Builds/`의 Unity 빌드
- Unity `.meta`, `.unity`, `ProjectSettings`, `Packages`
- Unity Editor·Runtime·uGUI C# 코드
- 웹에서 대체된 Unity 테스트 코드
- 최종적으로 불필요해진 `Game/` 전체

제거 전 조건:

1. 보존 커밋 또는 태그가 존재한다.
2. 웹 코드가 `Game/` 내부 파일을 참조하지 않는다.
3. 콘텐츠와 아트의 정본이 Unity 밖에 존재한다.
4. production build와 전체 테스트가 `Game/` 없이 통과한다.
5. 삭제 대상 목록을 정확히 기록한다.

제거 후 전체 검증을 다시 실행한다. 제거 때문에 실패한 항목이 있으면 Unity를 복구해 병행 개발하는 대신 누락된 의존성을 웹 구조로 옮겨 해결한다.

## 6. 필수 테스트 계약

### 6.1 단위 테스트

- 조건 종류별 참·거짓
- 명령 중복·순서·잘못된 scene 거부
- 증거 획득·열람의 멱등성
- 20개 퍼즐의 정답·부분 정답·오답
- 장면 완료와 허브 재방문
- 필수·선택 분기
- 힌트 단계와 사용 기록
- 저장 직렬화·복원·버전 오류·알 수 없는 ID

### 6.2 통합 테스트

- 콘텐츠 로드→게임 시작→상태 전이
- 퍼즐 해결→증거 지급→후속 장면 해금
- 자동저장→새로고침→이어하기
- asset ID→실제 이미지 URL
- region 정규화 좌표→실제 표시 영역

### 6.3 E2E 테스트

- 타이틀→첫 조사→첫 퍼즐
- 각 허브의 허용 순서 조합
- 필수 경로 전체 완주
- 선택 면담 미선택/개별 선택/모두 선택
- 오답→피드백→수정→성공
- 세이브 후 브라우저 재시작 복원
- 엔딩→사건 기록→타이틀 복귀

자동 테스트만으로 최종 완료를 선언하지 않는다. 실제 브라우저에서 렌더링·입력·텍스트·이미지 상태를 함께 검수한다.

## 7. 진행 보고 규칙

각 단계 종료 시 다음을 보고한다.

- 완료한 범위와 실제 파일
- 실행한 명령과 테스트 결과
- PASS, FAIL, NOT_RUN 구분
- 남은 작업과 현재 차단 요소
- Unity를 실행하거나 수정하지 않았다는 확인

빌드 성공, 브라우저 실행 성공, 전체 완주 성공은 서로 다른 결과로 보고한다. 소스가 존재한다는 이유만으로 동작 완료라고 보고하지 않는다.

## 8. 최종 완료 정의

다음을 모두 만족해야 프로젝트 완료다.

- Unity가 최종 소스·빌드·테스트·실행 경로 어디에도 사용되지 않는다.
- 웹 production build만으로 게임을 실행할 수 있다.
- 43개 장면, 36개 증거, 20개 퍼즐, 모든 분기와 엔딩이 구현됐다.
- 이미지 54개가 올바른 장면·표정·단서 좌표에 연결됐다.
- 저장·복원·힌트·설정·재방문이 정상 작동한다.
- `PARTIAL`, `MISSING`, 치명적 오류가 0개다.
- 필수 테스트와 실제 입력 완주가 통과했다.
- 기존 Unity 파일을 제거한 상태에서도 전체 검증이 통과한다.

이 조건 전에는 “웹 이전 완료”와 “게임 전체 완료”를 혼용하지 않는다.

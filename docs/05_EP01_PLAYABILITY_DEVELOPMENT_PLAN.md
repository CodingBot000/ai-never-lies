# Episode 01 플레이 경험 개선 개발계획서

작성일 2026-11-23 · 상태 **계획안** · 웹 구현 기준 `origin/master`의 `89f8f56`

이 계획의 목표는 정상적인 선택으로 사건 진행을 잃는 문제를 없애고, 플레이어가 단서를 찾아 판단을 바꾸는 경험을 늘리는 것이다. 실행 우선순위와 완료 기준은 [43개 장면·20개 퍼즐 전수 검토](../reports/EP01_PLAYABILITY_AUDIT.md)에 근거한다.

## 1. 범위와 기준

- 서사 장면 43개, 퍼즐 20개, 증거 36개와 기존 아트 자산을 사용한다. 출시된 장면·퍼즐·증거·분기 ID는 안정 키로 유지한다.
- 사건의 기술적 사실과 보고서 결론은 [마스터 계획](00_MASTER_PLAN.md)을 따른다. 플레이어의 선택은 먼저 얻는 정보, 질문, 인물의 반응, 수첩과 사건 기록에 영향을 줄 수 있다. 유족 자료 수신은 선택이며, 거절해도 본선의 사실·퍼즐·결말 조건은 동일하다.
- 증거를 **보유**, **열람**, **연결해 입증**한 상태를 구분한다. 증거 반박은 기존 최대 3개·최소 충분 근거 집합 규칙을 따른다. 충분한 조합에 무관한 보유 자료를 추가했다는 이유만으로 오답 처리하지 않는다.
- 단계마다 [웹 구현 명세](04_WEB_DESIGN_SPEC.md)와 실제 동작을 대조한다. 승인된 명세가 달라지는 항목은 관련 명세와 [변경 기록](../handoff/CHANGELOG.md)에 반영한다.
- 착수할 때 원격 HEAD와 작업 트리를 다시 확인한다. 작성 시점 로컬 `master`가 원격보다 10커밋 뒤에 있고 감사 보고서는 로컬 미추적 파일이다. 최신 원격 커밋에서 구현 브랜치나 별도 작업 트리를 만들고, 감사 보고서와 이 계획을 구현자가 읽을 수 있게 연결한다.

## 3. 작업 명세

### W0. 기준선·재현 고정

1. [감사 보고서](../reports/EP01_PLAYABILITY_AUDIT.md#검증-기록과-해석-범위)에서 재현한 화면과 현재 배포를 대조하고, 대상 코드·콘텐츠 버전·브라우저를 적는다.
2. 확보할 저장 샘플은 새 게임, `s130` 선택 중, `s340·s700` 진행 차단 직후, 퍼즐 조작 중, 사건 기록 완료다. 실제 저장 경로를 통해 만든 v1 샘플을 사용하고 개인 자료나 사용자 브라우저의 기존 저장과 격리한다.
3. 회사 먼저 방문할 때 영상 보유 여부, 각 잘못된 선택을 고른 뒤 계속했을 때의 상태, 844×390에서의 퍼즐 패널 높이를 기록한다. 37개 정적 경로와 정답을 고르는 키보드 완주는 회귀 기준으로 사용하고, 잘못된 선택에서 복구하는 테스트는 별도로 만든다.

**완료 기준** · 같은 코드에서 진행 차단과 모바일 잘림을 재현할 수 있고, 수정 전 저장 샘플을 로드해 기준 상태를 검사할 수 있다.

### W1. 선택 진행과 저장 복구

주요 파일 · [명령 처리기](../web/src/core/commands/commandDispatcher.ts), [대화 UI](../web/src/features/dialogue/DialogueLayer.tsx), [세션](../web/src/app/gameSession.ts), [게임 화면](../web/src/app/GameShell.tsx), [분기 데이터](../content/ep01/branches.json), [장면 데이터](../content/ep01/scenes.json).

1. 필수 그룹이 해결됐는지를 판정하는 공용 함수를 둔다. 그룹에 속하고 진행 효력이 있는 분기(`advances: true`)를 실제 선택했을 때 해당 그룹을 완료로 본다. 명령 처리기와 버튼 표시가 동일한 판정을 사용한다. 보조 항목은 선택 기록만 남기며 필수 조건을 충족하지 않는다.
2. `ChooseBranch`의 `branch_dialogue`와 `feedback`을 현재 대화 화면에서 표시한다. 추궁 응답 재생 경로를 참고하되 입력 처리와 표시를 분리한다. 비진행 응답이 끝나면 선택 가능한 항목을 다시 보이고, 진행 응답이 끝나면 변경된 상태를 표시한다. 응답 중 재클릭·Space로 효과가 두 번 실행되지 않는지 확인한다.
3. `s130`의 영상 제시에 `ev05` 보유 조건을 연결하고, 원본 요청 전에는 면담 완료를 허용하지 않는다. `s340`의 두 오답은 설명 뒤 재선택한다. `s700`의 사전 면담은 실제 방문 상태에서 확인하며, 선택 조작은 책임 우선·예방 우선 응답에 집중한다. 두 응답이 각각 기록 문구를 바꾸도록 유지한다. 과거 소개 분기 ID는 저장에 남을 수 있으므로 구형 기록으로 읽을 수 있게 한다.
4. 로드 직후 `s340·s700`의 종료 상태에서 필수 진행 선택이 빠진 저장만 정규화한다. 해당 장면의 완료·후반 대사 완료 표시처럼 조기 종료로 잘못 찍힌 상태를 바로잡고 선택 화면을 복원한다. 현재 `s130`에서 같은 상태인 샘플이 있으면 같은 규칙을 적용한다. 장면을 이미 지나 정상 진행 중인 저장은 당시 상태를 유지하고, 해결 퍼즐과 증거·슬롯은 보존한다. 정규화는 반복 로드해도 동일한 상태여야 한다.
5. 선택 응답과 상태 전환이 만나는 시점에 저장·불러오기를 확인한다. 응답 표시 도중 저장을 지원한다면 복원 후 응답의 의미가 빠지지 않도록 표시 단계 또는 재생 시작점을 복구한다. Effect나 방문 기록이 두 번 반영되지 않는지 검증한다.

**완료 기준** · `s340` 오답 두 개와 `s700` 구형 소개 선택 상태 각각에서 정상 선택으로 복귀할 수 있다. `s130`에서 원본 요청을 완료해야 이동한다. 유족 자료 수신·거절, 마지막 응답 2종, 수동·자동 저장 복원을 브라우저에서 확인한다.

### W2. 모바일 가로 조작

주요 파일 · [퍼즐 CSS](../web/src/features/puzzles/puzzle.css), [게임 화면 CSS](../web/src/app/shell.css), [퍼즐 화면](../web/src/features/puzzles/PuzzleHost.tsx), [모바일 가로 테스트 기준선](https://github.com/CodingBot000/ai-never-lies/blob/89f8f5619c647967a18f71bccf505e42b6d3cca4/web/tests/e2e/mobile-landscape.spec.ts), [반응형 QA](../web/tests/qa/responsive.qa.ts).

1. 높이가 짧은 가로 화면에 필요한 여백을 실제 HUD와 화면 안전 영역에서 계산한다. 다열 퍼즐을 1열로 바꾸는 규칙과 고정 하단 여백이 겹쳐 그리드 내용 높이가 11~56px에 그치는 현상을 우선 해결한다.
2. 짧은 가로 화면에서는 전체 퍼즐의 스크롤 주체를 명확히 정한다. 긴 대화나 알림이 없는 퍼즐에서 대화 패널 높이를 매번 예약하지 않고, 내부 패널이 콘텐츠에 맞는 높이를 갖도록 한다. 증언·자료·제출 사이를 이동해도 선택값을 유지하고 닫힌 모달의 초점을 되돌린다.
3. 20개 퍼즐 화면에서 가로 폭과 세로 패널을 검사한다. 화면별로 내용이 실제로 보이거나 정상 스크롤로 도달할 수 있어야 한다. `p01·p02·p03·p07·p17·p20`은 선택·오답 수정·제출까지 조작한다.

**완료 기준** · 844×390과 915×412, 기본 글자 크기와 기존 150% 저장 설정에서 핵심 조작에 도달하고 제출할 수 있다. 데스크톱 1280×720에서 레이아웃과 키보드 완주가 유지된다. 재현 환경의 스크린샷과 실제 입력 결과를 남긴다.

### W3. 목표·힌트·표시 이름

주요 파일 · [힌트 서비스](../web/src/core/hints/hintService.ts), [팁 화면](../web/src/features/hints/HintPanel.tsx), [게임 화면](../web/src/app/GameShell.tsx), [최신 표시 문자열 변환](https://github.com/CodingBot000/ai-never-lies/blob/89f8f5619c647967a18f71bccf505e42b6d3cca4/web/src/shared/i18n/contentText.ts), [최신 퍼즐 표시 이름](https://github.com/CodingBot000/ai-never-lies/blob/89f8f5619c647967a18f71bccf505e42b6d3cca4/web/src/shared/i18n/puzzleLabels.ts), [장면·힌트 데이터](../content/ep01/).

1. 현재 목표와 퍼즐 헤더에 표시하는 정보는 현재 쟁점과 조작 방법이다. 힌트는 관찰할 방향 → 자료·비교 범위 → 사용자가 열어 보는 해답 순서로 제공한다. 완료 화면에는 다음 행동을 표시한다. 필요하면 기존 정본 데이터에 표시 목적별 필드를 추가하고, 타입과 검증기를 함께 수정한다.
2. 상단 목표·팁 첫 화면·퍼즐 제목·대화의 공개 시점을 20개 퍼즐 전체에서 점검한다. `p04·p09·p12·p18·p19`의 증거 조합, `p05`의 미입수 후방위험 점수, `p07`의 시간대와 결론, `p08·p10·p11`의 직접 답변을 먼저 정리한다. 후반 결과를 앞에서 언급하는 대사는 플레이어가 직접 검증한 뒤로 옮긴다.
3. 증거 선택·배치 값·오답·기록까지 동일한 이름 해석 규칙을 적용한다. 증언 번호와 코드 식별자가 필요한 개발용 정보는 테스트 화면에서만 제공한다. 미입수 자료는 이름과 썸네일도 목표·힌트에 노출하지 않는다.

**완료 기준** · 정상 진행 시 현재 목표와 팁을 여는 것만으로 정답 증언·증거 조합이 드러나지 않는다. `p03`의 증거를 ID 없이 찾을 수 있고, `p05`에서 아직 얻지 않은 수치가 보이지 않는다. 각 후속 힌트는 의도한 내용만 순서대로 보인다.

### W5. 조사 순서의 효과와 수첩

주요 파일 · [허브 UI](../web/src/features/hub/HubScreen.tsx), [분기 데이터](../content/ep01/branches.json), [대사 데이터](../content/ep01/dialogues.ko.json), [상태 모델](../web/src/core/state/gameState.ts), [공용 타입](../web/src/core/content/dto.ts).

1. 첫 허브 카드에 그 장소에서 확인할 의문과 지금 확보한 관련 단서를 보여준다. 먼저 방문할 수 있는 세 곳은 기존대로 열어 둔다.
2. **승객→회사**에서는 `ev05`로 차내 경고의 범위를 질문하고 회사의 반응을 보여준다. **회사→승객**에서는 원본·출처 요구와 미해결 질문을 남긴다. 나중에 `ev05`를 얻으면 기존 질문의 수첩 표기가 갱신된다. 동일한 필수 원본 지급과 `s150` 진입을 두 경로에서 확인한다.
3. 우선 기존 방문·분기·열람·해결 상태로 조사 수첩 항목을 재구성한다. 특정 주장·근거의 연결을 추가 저장할 필요가 있을 때만 선택 필드를 도입하고 저장 왕복을 검증한다. 재방문·새로고침으로 증거를 다시 지급하거나 중복 항목을 만들지 않는다.
4. 첫 허브가 검증되면 `s200`에 같은 원칙을 적용한다. 프로그램을 먼저 봤다면 잘못된 후방 입력의 출처를, 카메라를 먼저 봤다면 영상에서 확인되지 않은 대상의 실행 영향을 묻게 한다. `s300`은 한 곳씩 열리는 진행 단계로 표시하고, `s400`은 변경 내용·설계 전제·시험 범위·승인 조건을 각 카드의 질문에 연결한다.

**완료 기준** · 두 첫 조사 순서를 각각 플레이하면 가능한 질문·응답과 수첩 상태가 달라진다. 바뀐 내용이 화면에 보이고 저장 후에도 유지된다. 모든 필수 자료와 퍼즐, 공통 사건 결론에 도달한다.

### W6. 인과판과 보고서 연결

주요 파일 · [퍼즐 판정기](../web/src/core/puzzles/puzzleEvaluator.ts), [퍼즐 UI](../web/src/features/puzzles/PuzzleHost.tsx), [상태 모델](../web/src/core/state/gameState.ts), [인과 데이터](../content/ep01/graph.json), [사건 기록](../web/src/features/archive/ArchiveScreen.tsx).

1. `p17`의 7개 인과선과 1개 신호선, 8개 근거 슬롯을 유지한다. 이전 퍼즐에서 **검증된 연결**만 근거와 함께 초안에 넣고, 아직 플레이어가 판단해야 할 연결을 표시한다. 불필요한 선과 근거 부족을 구분해 피드백한다.
2. `s450 → p18`, `s540 → p19`의 확인 구절을 해당 증언에 옆으로 붙인다. 어떤 증거가 인지·결정·사후 설명을 입증했는지 저장된 제출 결과와 연결한다.
3. `p20`의 5개 구역·9개 항목·8개 근거 요건을 유지한다. 앞에서 검증된 근거를 편집 가능한 초안으로 제안하고, 배치가 틀린 항목과 증거가 부족한 항목을 따로 표시한다. 정답 검증은 기존 명령 처리·판정 흐름으로 수행한다.
4. 예전 저장에서 인과판이나 보고서를 이미 작성 중인 경우, 새 초안보다 사용자 입력을 우선한다. 제안은 해당 퍼즐의 빈 항목에 한 번만 적용하고 사용자가 지운 항목을 다시 채우지 않는다.

**완료 기준** · 이어받은 각 항목에서 출처를 열 수 있고, 근거 한 개를 제거하거나 배치를 바꾸면 해당 항목만 수정 대상으로 표시된다. 적용 전후의 최종 결론과 판단 범위가 동일하다. 구형 중간 저장과 새 저장 양쪽으로 `s710`에 도달한다.

| --- | --- | --- |
| `p16`의 예측을 필수로 요구할지 | **선택 예측**은 기존 완주 조건과 저장을 그대로 쓰면서 발견의 순간을 추가한다. **필수 예측**은 추리 검증을 강화하지만 기존 세 사례 완료 규칙과 테스트를 바꾸고 튜토리얼을 더 필요로 한다. | 선택 예측으로 먼저 관찰한다. 필수화 여부는 플레이 테스트에서 판단한다. |

# 모바일 가로모드 대응 개발계획서

- 문서 ID: `ANL-MOBILE-LANDSCAPE`; 버전: `1.0.0`; 작성일: `2026-09-14`
- 상위 문서: `03_WEB_MIGRATION_AND_CONTINUATION_PLAN.md`(W7 브라우저 QA), `04_WEB_DESIGN_SPEC.md`(화면 기준)
- 상태: **계획 확정 전 검토용**. 승인 시 구현 기준으로 고정한다.

## 1. 목표와 범위

### 1.1 목표
- 모바일 기기를 **가로(landscape)** 로 들었을 때, 현재 데스크톱과 동일한 게임 경험(대화·조사·심문·20퍼즐·보고서·저장·설정)을 제공한다.
- 작은 가로 화면(예: 844×390, 915×412, 667×375)에서 잘림·겹침·과도한 스크롤 없이 핵심 콘텐츠를 읽고 조작한다.
- 터치만으로 완주 가능해야 하며, 세로(portrait) 상태에서는 "가로로 돌려 달라"는 안내를 제공한다.

### 1.2 범위
- 포함: 셸 레이아웃, HUD, 대화 레이어, 허브, 조사/증거, 심문, 퍼즐 위젯 15종, 보고서, 사건 기록, 모달, 설정·저장, 방향 안내.
- 제외(이번 계획): 세로 모드 전용 UI, 태블릿 전용 레이아웃(가로 기준으로 수용), 오디오, 성능 최적화(별도 문서).

### 1.3 기준
- 기준 비율 16:9 유지, 최소 지원 가로 640×360.
- 대표 검증 기기(에뮬레이션): iPhone 15/14 가로(844×390), Pixel 7 가로(915×412), Galaxy S8+ 가로(740×360).

## 2. 현재 문제 진단

| # | 문제 | 근거 |
| --- | --- | --- |
| 1 | 상단 HUD가 절대 배치이고 화면 높이가 낮으면 본문과 충돌 | 가로 390px 높이에서 HUD 2줄(약 88px) 발생, 본문 여백 72px로 부족 |
| 2 | 퍼즐 패널이 `max-height: calc(100vh - 300px)` 고정값 | 가로 390px에서 90px만 남아 스크롤 지옥 |
| 3 | 대화창 `min-height:180px`+선택지가 화면을 과점 | 390px 높이에서 대화+선택지만 보임 |
| 4 | 모바일 브라우저 주소창 변화로 `100vh` 오차 | iOS Safari, Android Chrome |
| 5 | 노치·홈 인디케이터 미대응(`safe-area-inset`) | iPhone 가로 좌우 노치 |
| 6 | 44px 터치 영역 미달 버튼 존재(작은 tab, 태그형 버튼) | `min-height:36px` 다수 |
| 7 | 세로 모드에서 레이아웃이 강제로 찌그러짐 | 안내 없음 |
| 8 | 퍼즐 위젯 3단 그리드가 가로에서 1열로 떨어져 세로 스크롤 과다 | `.anl-puzzle--three` 1100px 브레이크포인트 |
| 9 | 확대(핀치줌)와 텍스트 150% 조합에서 겹침 가능 | 미검증 |

## 3. 설계 원칙

1. **가로 우선, 세로는 안내**: `@media (orientation: portrait) and (max-width: 1024px)` → 회전 안내 오버레이.
2. **동적 뷰포트 사용**: `100vh` 대신 `100dvh`(+`100svh` 폴백), `--anl-vh` 변수로 통일.
3. **세이프 에어리어**: `padding: env(safe-area-inset-*)`을 셸·HUD·대화창에 적용.
4. **HUD 축소**: 가로 ≤ 900px에서 버튼 높이 36px, 글자 `--anl-text-xs`, 한 줄 유지(넘치면 가로 스크롤 대신 아이콘+라벨 축약).
5. **본문 높이 예산 공식**: `본문 = 뷰포트 − HUD − 대화영역`을 CSS 변수(`--anl-hud-h`, `--anl-dialogue-h`)로 계산해 화면별 상한을 고정값 대신 변수로 사용.
6. **스크롤 분리**: 화면 전체 스크롤 금지. 패널 내부만 스크롤(오버스크롤 방지 `overscroll-behavior: contain`).
7. **터치 최소 44×44px**: 모든 인터랙티브 요소 `min-height/min-width: 44px` 또는 여백으로 확보. `touch-action: manipulation`으로 더블탭 확대 방지.
8. **가로 2단 우선**: 퍼즐은 "좌: 입력/목록, 우: 상세/제출" 2단을 기본으로 하고 3단은 ≥1100px에서만.
9. **기존 테스트 자산 재사용**: Playwright 디바이스 프로필·스크린샷 파이프라인 그대로 사용.

## 4. 구현 단계 (ML0~ML5)

### ML0 — 뷰포트·토큰 기반
- `base.css`/`tokens.css`: `100dvh` 도입, `--anl-hud-h`, `--anl-dialogue-h`, `--anl-safe-l/r/t/b` 변수 추가.
- `index.html`: `viewport-fit=cover` 추가.
- 통과: iOS/Android 에뮬레이션에서 셸 높이 오차 0, 가로 스크롤 0.

### ML1 — 셸·HUD·방향 안내
- HUD: 가로 소형에서 축소형(36px) 스타일, `safe-area-inset-top/right` 반영.
- 방향 안내 오버레이(`PortraitNotice`): 세로 + 터치 기기에서 전체 화면 안내, 가로 전환 시 자동 해제.
- 통과: 844×390에서 HUD 1줄, 본문 겹침 0.

### ML2 — 대화·허브·조사
- 대화창: `--anl-dialogue-h` 상한(가로 소형 32vh), 본문 폰트 `--anl-text-md` 유지, 선택지는 가로 스크롤 대신 2열.
- 허브 카드: 2열 고정(작은 가로), 썸네일 96px.
- 조사: 배경 contain 영역이 HUD 아래 전체 높이 사용, 우측 패널 폭 260px 고정.
- 통과: s000→s110 실제 터치(탭) 완주, 오버플로 0.

### ML3 — 퍼즐 위젯 15종
- 공통: `.anl-puzzle` 상단 여백 변수화, `max-height` 고정값 제거.
- 유형별: statement(좌 증언/중 선택/우 증거 → 작은 가로는 증언↔증거 2탭), ordering(카드/배치 2단), matrix(표 가로 스크롤 허용), causal(노드 그리드 2열, 간선 목록 접이식), report(구역 2×3, 팔레트는 하단 시트), diff(코드 좌우 스크롤), counterfactual(사례/결과 2단).
- 통과: 20퍼즐 각각 844×390에서 정답 제출까지 도달(개발 자동 진행 + 대표 수동).

### ML4 — 모달·설정·저장·기록
- 모달: `max-height: calc(100dvh - 24px)`, 내부 스크롤, 닫기 버튼 상단 고정.
- 증거책: 가로에서 목록(40%)/상세(60%) 2단 유지, 상세 이미지 높이 상한.
- 저장/설정/사건 기록: 1열 + 내부 스크롤.
- 통과: 저장→새로고침→이어하기 터치 조작 성공.

### ML5 — 검증·문서
- Playwright 프로젝트 추가: `mobile-landscape`(2종) — 전 화면 오버플로·겹침 검사, 대표 흐름 완주, 스크린샷 수집.
- `04_WEB_DESIGN_SPEC.md`에 모바일 가로 규격 절 추가, `docs/WEB_IMPLEMENTATION_STATUS.md` 갱신.
- 실제 기기 1대 이상 수동 QA 체크리스트 수행.
- 통과: 아래 6장 완료 기준 전부 충족.

## 6. 완료 기준

1. 대표 가로 3종에서 모든 화면 가로 스크롤 0, 요소 겹침 0.
2. HUD 5개 버튼이 어떤 화면에서도 가려지지 않는다.
3. 터치만으로 타이틀→엔딩 완주가 가능하다(자동 E2E + 수동 1회).
4. 대화·퍼즐·증거책·저장·설정 어디에서도 화면 밖으로 나가는 콘텐츠가 없다.
5. 세로 모드에서는 명확한 회전 안내가 표시되고, 가로 전환 시 즉시 정상 동작한다.
6. Safari(iOS)·Chrome(Android)에서 콘솔 오류 0, 저장 복원 정상.
7. 기존 데스크톱 E2E(11종)와 단위 테스트가 모두 통과한다(회귀 0).
